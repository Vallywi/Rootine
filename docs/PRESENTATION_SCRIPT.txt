Good day, everyone. My name is (YOUR NAME), and this is Rootine, my final project for Programming Tools
and Techniques.

Here is the problem. Many students sit down to study, and within minutes they are on their phones.
A plain timer does not help much, because it only shows numbers. Nothing rewards you for staying focused,
and nothing costs you when you quit.

Rootine fixes this with a simple idea. It is a Pomodoro focus app, which means you work in timed blocks
with short breaks between them. But while you focus, a plant grows on your screen. If you finish the
session, you collect the plant and it joins your garden. If you give up, the plant withers.

The users are students and anyone who works in focused blocks. It runs in any browser, on phones and
computers, and it can be installed like an app because it is a Progressive Web App.

4:00 - 5:00   ARCHITECTURE AND TECHNOLOGIES
==========================================================================
[SHOW: docs/architecture.md in VS Code, with the Mermaid diagram previewed]

Now, how it is built. Rootine has three layers.

The frontend is React 19 with Vite, and a PWA plugin that makes it installable. Each screen is one file
in frontend/src/pages.

The backend is Node.js with Express 5. Each feature has its own router: auth, tasks, sessions, garden, shop,
friends, and chat. Every request body is checked with a library called zod, and I use helmet for security
headers, a CSRF header on every write, rate limits, and hashed passwords.

The database is PostgreSQL. In production it is Supabase, and it is hosted on Vercel. For local use and tests
I use PGlite, which is real PostgreSQL running inside Node, so nobody needs to install a database.

Secrets, like the database URL and the AI key, live in a .env file that is in .gitignore. The repository
only has a .env.example with empty placeholders.

5:00 - 6:00   THE EXTERNAL API: GOOGLE GEMINI
==========================================================================
[SHOW: the chat drawer in the app, then backend/src/ai.js in VS Code]

The external API I use is Google Gemini. It powers Rootie, the chat assistant.

Why Gemini? It has a free tier, it works with plain JSON over HTTPS so I did not need an extra library,
and it is good at short natural answers.

[ACTION: type "How is my progress this week?" and send. Read the reply aloud.]

Here is what happens when I send this question. The browser calls my own server at /api/chat. The server
checks that I am logged in, checks the rate limit of 30 questions per hour, and validates the input: at most
10 messages, at most 500 characters each.

Then the server builds a snapshot of MY data from the database: focus minutes, streaks, plants, open tasks,
and badges. The browser cannot add facts to it, and other users' data, emails, and friends' progress are never
included. The server sends that snapshot with the question to this endpoint:

  POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent

The API key goes in a request header, never in the URL, and it only exists on the server. Gemini answers with
JSON, and I read the text from candidates, first item, content, parts.

[SHOW: the error handling code in ai.js]
Now, error handling, which the course requires. The request times out after 15 seconds. If Gemini says it is
busy with a 503, the server retries once. If it is rate limited with a 429, the user sees "The assistant is busy
right now." For other errors, the user sees "not available", and I do not show provider details, so the key
cannot leak. An empty answer gives its own message. And if there is no key at all, the rest of the app still
works.

[SHOW: docs/rootine.http with the REST Client extension, click Send Request]
I can also test the API directly from VS Code with the REST Client extension.

6:00 - 6:45   DESIGN PATTERN: STRATEGY
==========================================================================
[SHOW: backend/src/db.js, the createDb function]

The design pattern is Strategy. Strategy means several interchangeable implementations behind one interface.

In db.js, a function called createDb looks at the configuration. If there is a DATABASE_URL, it returns the
Supabase PostgreSQL driver. If not, it returns the local PGlite driver. Both have the same four methods:
query, tx for transactions, migrate, and close.

So all the routes just call ctx.db.query and never know which database they are using. This solves a real
problem: the same code runs in production, on a grader's laptop with nothing installed, and in tests with a
fresh in-memory database each time.

Why not the alternatives? Putting an if-production check in every route would duplicate logic across ten
files. A Singleton gives one shared instance but cannot be swapped, so tests would share state. And mocking
the database would not run real SQL.

The AI client follows the same idea: the chat route only needs one method, reply, so my tests inject a fake AI.

==========================================================================
POSSIBLE QUESTIONS - SHORT ANSWERS
==========================================================================
Q: Why does the server handle the timer?
A: So users cannot cheat by changing the browser clock, and the timer survives refreshes.

Q: Where is the API key kept?
A: In backend/.env locally and in Vercel environment variables in production. It is never in the repository.

Q: What if Gemini is down?
A: The user gets a clear message, and everything else in the app still works.

Q: What does Strategy give you over an if statement?
A: One place decides which driver to use, routes stay unchanged, and tests can use a fresh in-memory database.

Q: How do you stop the AI from leaking other users' data?
A: The server builds the snapshot from the logged-in user's own rows only. A test checks that another user's
   name and any email are not in the prompt.

Q: What is prompt injection, and what did you do about it?
A: A user could write task titles that look like instructions. The system prompt tells the model that the data
   and task titles are untrusted text and must never be followed as instructions.
